# AI 小说创作工具

> **本工具是记忆管理工具，而非写作 AI。**
>
> 它不替你写小说，它帮你**记住**你写过什么 —— 解决长篇创作写到中后期的人设崩坏与剧情矛盾（网文圈叫「吃书」）。

一个**开源、免费、本地运行**的中文长篇小说写作助手。
稿件与设定全部留在你自己的电脑里，不上传任何服务器；AI 能力由你自带密钥（BYOK）接入。

---

## 它解决什么问题

大模型能写出漂亮的段落，却写不完一部长篇。瓶颈不在文笔，在三件事：

| 问题 | 表现 |
|---|---|
| **长文失忆** | 写到第 50 章，第 5 章的细节早滑出上下文。实测普遍在 3 万字后质量断崖下跌 |
| **人设漂移** | 第 10–15 章起，角色性格软化、已死角色被当活人引用、能力等级前后矛盾 |
| **情节套路化** | 模型按概率选「最不出错」的选项，反转可预测、情节自我复制 |

根因是：**模型没有持久记忆，只有上下文**。

所以本工具的做法是 **记忆外置** —— 把设定与状态从模型上下文里剥离，存进本地数据库，在需要时按需注入：

```
设定库（人物 / 世界观 / 线索）
   ↓  写新章之前自动把「本章要出场的人现在什么状态、哪些线索还没回收」递给你
写作台
   ↓  写完点「完成本章」，AI 给出状态变更建议
归档（你逐条确认后才入库）
   ↓  进入下一章，循环
```

**这个循环是本工具的心脏。** 它和普通文本编辑器的根本区别在于：提醒是**自动**的，你不用回头翻旧稿。

---

## 三条不可违反的设计红线

1. **写前提醒必须自动触发** —— 不能做成「你点一下按钮才查」。进章节就自动展示。
2. **归档必须经你确认** —— AI 生成的状态更新要逐条过你的眼，你确认或修改后才入库。
   全自动会让 AI 的错误沿章节链条累积放大，几十章后不可收拾。
3. **不配模型也能用** —— 设定库、编辑器、归档、版本管理、导出、字数统计、检索全部不需要 AI。

## 功能一览

### 不需要 AI（这部分是产品的稳定价值底座）

- **设定库** —— 人物卡（四要素：表面身份 / 秘密欲望 / 致命弱点 / 矛盾行为）、世界词条（势力 / 地点 / 规则 / 物品）、线索台账
- **写作台** —— 左中右三栏：章节树 · 编辑器 · 提醒面板
- **章节版本管理** —— 快照、列表、回滚
- **导出** —— txt / docx，可指定章节范围
- **字数统计与日更记录**
- **全文检索**
- **质检：去 AI 味** —— 扫出套话连接词、直接说情绪、程度词过多三类"机器味"，给 0-100 评分与逐条改写建议
- **质检：敏感词自查** —— 用你自己准备的本地词库扫全书，按章节与分类汇总（**纯本地匹配，不上传、不联网**）
- **外观主题** —— 5 套可选主题（含夜间 / 纯黑 / 米黄纸 / 松林），一键日夜切换
- **一键启动** —— 双击脚本，浏览器自动打开

> **质检页只做检查，永不改动你的正文。** 它只告诉你"哪一段有问题、问题是什么"，
> 并把你跳到那一段去改。理由写在 `04-界面设计说明.md` §5.4：去 AI 味是人的活，
> 而且平台严查 AI 生成正文 —— 工具替作者改稿，风险只会更大。

### 需要 AI（你自带密钥）

- **写前召回** —— 进章自动汇总本章出场人物状态与未回收线索
- **章末归档** —— AI 读本章正文，给出状态变更建议（你确认后入库）
- **AI 对话式建设定** —— 跟 AI 聊几句，它把人物卡与世界观生成好，你改改就行
- **选题向导** —— 四个问题 + 题材库真实数据，推荐蓝海细分方向
- **大纲 AI 展开** —— 粗纲生成卷纲、章节卡候选

## 安装与启动

### 环境要求

| 组件 | 版本 |
|---|---|
| Python | **3.12.x**（3.13+ 与向量扩展组合未验证，启动时会校验并拒绝） |
| Node.js | 20 LTS 或以上（仅构建前端时需要） |

### 首次安装：不需要手工安装

**只要装了 Python 3.12 就够了，剩下的全自动。** 双击启动脚本即可，
`bootstrap.py` 会自己完成：建虚拟环境 → 装后端依赖 → 校验前端产物 → 起服务 → 打开浏览器。

```bash
./start.sh --check        # 只想先做一次环境体检，不启动
./start.sh --reinstall    # 强制重装后端依赖
./start.sh --no-browser   # 启动但不自动开浏览器
```

> **为什么不用手工 `python -m venv` + `pip install` 了？**
> 那种做法换一台电脑就等于重新装一遍，与「开箱即用」相悖。
> 现在「装」和「启」合成一步，且**幂等** —— 重复运行只做必要的那部分。
> 从别的电脑拷过来的 `.venv` 会被自动识别（`pyvenv.cfg` 指向不存在的解释器）并改名保留为 `.venv.broken`，再重建一个新的。

#### 什么时候才需要 Node.js

**运行阶段完全不需要 Node.js** —— 前端构建产物 `frontend/dist/` 随仓库分发。
只有**要改前端代码**时才需要：

```bash
cd frontend
npm install
npm run build          # = tsc --noEmit && vite build
```

### 启动

```
双击 start.bat        （Windows）
./start.sh            （macOS / Linux；首次需要 chmod +x start.sh）
```

浏览器会自动打开。**全程不需要命令行操作。**

> 两个脚本都不做多余的判断，只负责**找到一个 Python 3.12**，
> 然后把其余全部交给 `bootstrap.py` —— 这样 Windows 与 macOS/Linux 行为一致。
> 找不到 3.12 时会给出各平台的安装命令，**绝不静默用其它版本顶替**。

### 配置 AI 模型（可选）

打开 **设置 → 模型配置**：

1. 选服务商（支持 DeepSeek / 通义千问 / Kimi / OpenRouter / 阶跃星辰 / Claude / 本地 Ollama 等，也可填任意 OpenAI 兼容端点）
2. 填接入地址与 API Key
3. 点「**拉取模型**」从平台获取可用模型列表，或直接手填模型名
4. 点「**测试连接**」确认密钥可用
5. 保存

> ⚠️ **「拉取模型」成功不等于密钥有效** —— 部分平台的模型列表是公开接口，错的密钥也能拉到列表。**只有「测试连接」通过，才说明密钥真能用。**

密钥保存进系统密钥环（Windows 凭据管理器 / macOS 钥匙串），数据库里只存一个引用名，**界面永不回显**。

## 数据在哪

```
books/<书名>/
  ├── novel.db          你的全部内容（章节、设定、状态、向量索引）
  ├── meta.json         书名等元信息
  └── exports/          导出文件
```

**一本书一个独立数据库。** 备份 = 复制文件夹；迁移 = 拷到另一台机器。
删除作品时移入回收目录，**不物理删除**。

```text
data/
  ├── genres.json               题材知识库（选题向导用）
  ├── sensitive_words.txt       敏感词库（**需你自己准备**，见下）
  └── sensitive_words.example.txt  格式示例
```

> **敏感词库要你自己准备。** 软件只提供检测能力、不提供词表 —— 原因写在
> `11-敏感词库说明.md`：词表来源不明会造成"看似审查了、实际不合规"的假安全感。
> 用法：把 `sensitive_words.example.txt` 复制成 `sensitive_words.txt`，替换成你自己的词，
> 每行格式 `词条[,分类]`，支持 `词A|词B` 变体写法。这个文件已在 `.gitignore` 里，**不会随仓库分发**。
> 质检页会明确提示：**本功能基于本地词库做机械匹配，仅供参考，不构成合规审查结论。**

> **备份提醒**：SQLite 用 WAL 模式，会产生 `novel.db-wal` 和 `novel.db-shm` 两个伴生文件。
> **整目录复制**，只拷 `.db` 会丢最近的事务。

## 常见问题

**Q：要花钱吗？**
软件免费开源。AI 调用费由你自己付给模型厂商（写一章大约几分钱到几毛钱），软件不抽成、不经手。

**Q：我的稿子会被上传吗？**
不会。软件没有服务端，所有内容只存在你本机。AI 部分是你的电脑直接连模型厂商。

**Q：我不懂技术能用吗？**
可以。会折腾的地方我们都做了选择项（题材有 22 个赛道下拉、人物四要素有预设词条），但**申请一个 AI 账号并拿到密钥**这一步需要你动手 —— 如果身边有懂电脑的朋友，10 分钟能搞定。

**Q：它能替我写吗？**
技术上能，但**不建议**，而且各大网文平台也明令禁止整章生成。它最大的价值是**帮你记住**，不是替你写。

**Q：为什么不做手机版？**
小说创作依赖大屏与键盘。本工具最小可用宽度 900px。

## 外观主题

内置 5 套主题，设置页「外观」里切换，也可以直接点写作台顶栏的月亮/太阳图标一键日夜切换。
选择会记住。

| 主题 | 适合 |
|---|---|
| 保险蓝（默认） | 白天办公 |
| 夜航灯 | **夜间写稿主推**，深灰蓝低眩光 |
| 纯黑 | OLED 屏省电、对比最高 |
| 米黄纸 | 模仿纸质书暖色，长时阅读眼压最低 |
| 松林 | 低饱和绿灰，缓解屏幕发白 |

还有「跟随系统」：系统切深色，页面跟着切。所有主题色值都写在
`frontend/src/styles/design-tokens.css`，加主题见 `docs/开发导览-代码地图与扩展教程.md` 场景 A。

## 一句写在最后的话

> **先写完，再写好。** 第一本书的目标不是成神，而是**完本**。
