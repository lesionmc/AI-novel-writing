## 要求

1. **必须引用题材库中的真实数据**（热度、竞争密度、蓝海指数），不要虚构数字。
2. 优先推荐「蓝海细分」——有读者基础但竞争未饱和的赛道。
3. 每个方向给出：
   - 细分名称（如「无限流 + 中式民俗」，而不是笼统的「无限流」）
   - 推荐理由（结合作者情况与数据）
   - `benchmarks`：3 条**该方向的常见套路或设定**（优先取自题材库的 `typical_tropes`，
     例如「开局进副本」「规则怪谈式解谜」）。
   - 一句话卖点示例
4. **`benchmarks` 的硬约束（违反即视为不合格输出）**：
   - 题材库里这些方向的真实对标书单是**空的**，你没有可靠的作品数据源，因此
     **严禁编造书名**。不确定某部作品是否真实存在，就**不要写它**。
   - 只有在**你确信某部作品真实存在**时，才可以在套路之外附上它的名字；
     否则 `benchmarks` 里只放套路/设定描述。
   - 宁可全部写套路，也不要输出一个假的"对标书单"——用户会照着假书单去花真时间research。
5. 明确指出**不推荐**的方向及理由（如"传统玄幻竞争过于激烈，新人签约率低"）。
6. 不要推荐「一键生成」「无脑爽文」这类方向。

## 输出格式

只输出 JSON：

{
  "recommendations": [
    {
      "niche": "细分方向名称",
      "reason": "推荐理由，需引用题材库中的具体数据",
      "benchmarks": ["常见套路或设定1", "常见套路或设定2", "常见套路或设定3"],
      "sample_premise": "一句话卖点示例"
    }
  ],
  "avoid": [
    { "direction": "不推荐的方向", "reason": "理由" }
  ]
}

> 字段说明：`benchmarks` 沿用契约里的字段名（不改契约），但其**语义已收敛为
> 「该方向的常见套路/设定」**。只有确信真实存在时才可放作品名，且**严禁编造**。
