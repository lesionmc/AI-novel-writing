## 输出要求

1. **只记录本章实际发生的变化。** 没有变化的角色不要出现在结果里。
2. 角色状态描述必须**具体可查**：
   - 正确：「左臂受伤，无法持剑，对李四存有戒心」
   - 错误：「受了伤」「心情复杂」
3. 新埋的伏笔必须给出重要程度，只能从 high / medium / low 中选一个。
4. **本章最多列 3 条新伏笔，只列真正会在后续章节回收的**；一次性的道具、环境细节、随口提到
   的名字不要当成伏笔。宁可少列，也不要凑数——灌水会稀释后续章节能用到的伏笔提示。
   （超出 3 条会被系统按重要度自动截断；low 重要度默认不予保留。）
5. **不要补充正文里没有的情节，不要推测后续发展。**
6. 摘要要客观陈述发生了什么，150–200 字，不评价、不抒情。
7. 所有字段都必须出现。没有内容的用空数组或 null。

## 输出格式

`new_foreshadows` 最多 3 条，只列真正会在后续章节回收的。

只输出以下 JSON，不要任何其他文字、不要 Markdown 代码块标记：

{
  "chapter_summary": "本章摘要，150-200字",
  "character_updates": [
    {

      "reason": "因本章何事导致该变化"
    }
  ],
  "plot_progress": [
    {
      "arc": "剧情线名称",
      "progress": "推进到哪一步"
    }
  ],
  "new_foreshadows": [
    {

      "importance": "high"
    }
  ],
  "closed_foreshadow_ids": [12],
  "hook": "本章结尾留下的钩子，若没有则填 null"
}
