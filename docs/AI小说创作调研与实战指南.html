AI 能写小说，但写完一本小说仍然是人的活

这份指南把「AI 小说创作」这件事拆开揉碎讲清楚：现在有哪些工具、它们各自怎么实现的、开源圈子里的大神都在用什么思路、以及写一本小说从选题到完稿到底要走哪几步。 不用任何技术背景，看完就能上手。

调研时间 2026 年 9 月 覆盖 20+ 工具 覆盖 16 个开源项目 五大技术流派
结论 01

AI 已经能写好「段落」，但还写不好「长篇」。普遍现象是：写到 3 万字左右质量断崖式下跌，第 10～15 章开始人设漂移、前后矛盾。

结论 02

行业共识已经形成：AI 干体力活，人干灵魂活。大纲、素材、句子优化交给 AI；人物、情绪、转折、爽点必须自己来。

结论 03

所有成熟方案的共同秘密只有四个字：记忆外置。把设定从模型的脑子里，搬到一个外部数据库里，写到哪一章就查哪一章。

01 / 现状

先搞清楚：AI 写小说现在到底行不行？

网上各种宣传很热闹，但真实情况可以用一句话概括：AI 是一支很好用的笔，但它还不是一个作家。下面把它为什么行、为什么不行讲明白。

三条技术路线，各干各的活

1通用大模型直接写

代表：DeepSeek、Kimi、通义千问、Claude、ChatGPT、Gemini

你直接对着聊天框说「帮我写个玄幻小说开头」，它就能写。

优势：便宜甚至免费、中文语感好、灵活。

死穴：没有持久记忆。关掉对话再打开，它就完全不认识你的主角了。适合用来「想点子、搭设定、排逻辑」，不适合做长篇管理。

2垂直专用工具

代表：Sudowrite、Novelcrafter、NovelAI、笔灵AI、彩云小梦

专门为写小说做的软件，核心是「模型 + 记忆层」：Story Bible / Codex / Lorebook 这类设定库，本质就是一套检索系统（RAG）。

优势：能记住你的角色和世界观，是目前解决长篇一致性的唯一有效路径。

死穴：要花钱、要学、功能边界窄。

3多智能体工作流

代表：Agents' Room、StoryWriter、以及一批 Agent 框架

不再让一个 AI 从头写到尾，而是组一个「编剧组」：有人管世界观、有人当写手、有人当审校、有人专门挑逻辑漏洞。

优势：分工带来质量提升，模块可以随时替换。

死穴：烧钱——调用次数成倍上涨，而且几个 Agent 之间还可能互相带偏。

六个绕不过去的痛点

这六个问题，是目前所有工具和方案都在拼命解决的。看懂它们，你就看懂了整个领域在卷什么。

!长文失忆

最致命的一个

模型的记忆是一个「滑动窗口」，写到第 50 章时，第 5 章的细节早就滑出窗口了。实测普遍在 3 万字后质量明显下滑。

!人设崩坏 / 吃书

角色性格慢慢「软化」成通用默认值；死掉的角色被当成活人引用；能力等级前后对不上。

!剧情重复套路化

AI 天生倾向于选「最不出错」的选项，所以反转基本都能猜到，情节容易自我复制。

!AI 味重

三个特征：句式太整齐、用词太安全（「进行/使得/作为一个」）、情绪太平（写「他感到愤怒」而不是「他把烟按灭在掌心」）。

!写不长 / 水字数

到一定长度就开始重复描写同一个动作、同一段心理，看上去在写，其实在灌水。

!情感深度的「恐怖谷」

它能熟练地写出「悲伤」的词汇，但很难真正理解复杂动机。概率平均化天然抹掉了那种让人意外的「陌生感」。

🔑 一句话理解这些痛点是怎么来的

大模型的本质是「根据前文预测下一个词」。它没有真正的记忆，只有上下文；它没有意图，只有概率。所以「忘得早」和「写得平」是它的出厂设置，而不是某个 bug。所有聪明的方案，本质上都是在用工程手段绕过这两条。

03 / 平台态度

写网文之前，先看清平台的「红线」

这一节很实际：你用什么工具不重要，能不能过审才重要。五大平台的 AI 政策差异极大，用错工具可能直接封号。

平台官方 AI 工具开放程度态度档位
阅文（起点/QQ阅读） 作家助手 + 妙笔通鉴（千万字级理解，做细节回顾、剧情总结、伏笔挖掘） 只开放校对、润色、素材整理；不允许整章生成/剧情代写 最严 有来源称 AI 正文占比超 30% 直接拒稿
番茄小说 番茄作家助手：AI 扩写、改写、续写、起名、卡文锦囊等七项功能 官方表态「做的是 AI 辅助写作，而非纯 AI 小说」 中度 2026 年 5 月将「AI 批量生成、缺乏原创性」列为低质标准
七猫 未确认具体工具 禁 AI 情绪模板，重细腻剧情（女频为主） 质感管控

📌 行业层面：16 家头部平台已联合发布《网络文学行业反洗稿自律公约》。晋江明确表示「很长时间内不会考虑将 AI 工具直接引入创作领域」。

⚠️ 三条实操底线

  • 用 AI 理大纲、查资料、做校对 —— 安全。所有平台的官方工具都在做这些。
  • 让 AI 整章生成正文 —— 高危。投晋江会锁章，投起点有被判拒稿的风险。
  • 投晋江的务必守住「校对/要素/粗纲」三级红线；投起点的不要碰整章生成。

另外记住一条行业统一公式：AI 干体力活（大纲、素材、句子优化），作者干灵魂活（人设、情绪、转折、爽点）。

04 / 开源项目

GitHub 上的大神们，是怎么解决「写不长」的？

商业工具的源码你看不到，但开源项目全都能看。这一节把 GitHub 上最有代表性的项目拆开，看看它们各自押注哪条技术路线。 理解这些思路，比会用任何一个工具都值钱——因为这些思路可以直接迁移到你自己的工作流里。

五大技术流派（这是本节的核心）

所有开源方案，本质上都在用下面五种思路中的一种或几种。看懂这五张卡，你就掌握了这个领域的「武功图谱」。

流派 ① 大纲驱动 · 分层生成

解决什么问题
全局结构失控、前后不呼应——写着写着就跑偏了。
怎么做
先大纲后正文，而且大纲分层递进：粗纲 → 细纲 → 章节要点，生成时一层层往下钻。
代表作
DOC（三层大纲 + 控制器）、DOME（动态展开细纲）
优点 / 缺点
✅ 结构完整、可控性强、人能插手的点很清晰
❌ 大纲一旦定死就无法适应剧情涌现；细纲展开依赖模型质量

流派 ② 递归循环 · 带记忆生成

解决什么问题
上下文窗口有限，写长了就忘。
怎么做
每写一段就重新拼一次 prompt（递归重提示），同时把历史压成摘要 / 状态文件 / 向量库，反复召回。
代表作
Re3、AI_NovelGenerator（状态文件 + 向量库）、LongWriter（AgentWrite 分段）
优点 / 缺点
✅ 理论上可无限长、工程门槛低
❌ 摘要会丢细节；错误会沿着链条累积放大

流派 ③ 多 Agent 协作

解决什么问题
单个模型「一种人格写到底」，创意贫乏、不会自我审查。
怎么做
按职能拆 Agent：规划者、角色设计师、写手、编辑、审校、书目管理员，用共享黑板 + 编排器串起来。
代表作
Agents' Room（Google DeepMind）、StoryWriter（清华 KEG）、CrewAI 系示例
优点 / 缺点
✅ 分工带来可测量的质量提升、模块可替换
❌ 调用次数与成本成倍上涨；Agent 之间可能互相污染

流派 ④ 知识图谱 + 检索增强

解决什么问题
人物关系、战力体系、时间线这类结构化的一致性。
怎么做
把剧情抽成三元组/四元组存进图数据库（Neo4j、时序知识图谱），写新章前检索相关事实注入。
代表作
DOME（时序知识图谱）、NovelForge（Neo4j 关系入图）、GraphRAG、Letta（前 MemGPT）
优点 / 缺点
✅ 能精确回答「第 10 章主角有没有断剑」这类硬问题
❌ 抽取本身靠 LLM 会抽错；维护成本高；对文学性毫无帮助

流派 ⑤ 微调专用写作模型

解决什么问题
通用模型「不愿写长、写不长」——输出长度被训练数据锁死了。
怎么做
不是提示词技巧，而是数据 + 训练：构造长文 SFT 数据集 + DPO/RL，把长文能力训进权重里。
代表作
LongWriter（清华 + 智谱）、StoryWriter 微调版、AI-Writer（RWKV 中文网文语料）
优点 / 缺点
✅ 一次推理出万字，快、无编排复杂度
❌ 需要 GPU 和训练资源；模型训练完就「冻结」，无法动态接知识库

实战共识 真正能跑通百万字的，都是混血

关键结论
GitHub 上真正跑通「百万字中文网文」的项目，几乎都是 ①大纲分层 + ②记忆递归 + ④向量检索 的混合体，再用 ③多 Agent 做审核修复；流派 ⑤ 则作为「长文输出能力」的底层补丁被嫁接进来。
为什么
因为每个流派只解决一个维度的问题：①管结构、②管长度、③管质量、④管一致性、⑤管产能。单一流派都无法独立解决长篇小说问题。

三个最值得琢磨的项目

中AI_NovelGenerator —— 中文圈最接地气的方案

YILING0013/AI_NovelGenerator · 6.1k ⭐ · Python · 完全可本地部署

核心思路：分步人工确认 + 状态文件 + 向量召回。它不是一键生成，而是把流程切成可控的段落：

设定工坊
世界观/角色/伏笔 → 生成章节目录 → 逐章生成
生成前向量检索召回历史 → 确认定稿
回写状态文件+更新向量库 → 一致性审校

关键实现：每章定稿时会回写三个状态文件——global_summary.txt（全书摘要）、character_state.txt（角色状态）、plot_arcs.txt（剧情线），并同步更新向量库。支持按任务路由不同模型（架构用 Gemini、正文用 DeepSeek、审校用第三个模型）。

值得学的地方：「用不同模型干不同活」这个思路，你完全可以在手动工作流里照搬。局限：向量检索以「章节摘要」为粒度，跨章细节仍可能漂移。

重AI-Novel-Writing-Assistant —— 工程最重的「整本书生产线」

ExplosiveCoderflome/AI-Novel-Writing-Assistant · 3.0k ⭐ · TypeScript · 可暂停可恢复

核心思路：不写「一段文案」，而是做一条可暂停、可恢复的整本书生产链。一句灵感输入进去，自动跑：

自动导演（方向/世界/角色/卷战略/章节任务）→ 章节生成 → AI 审核 → 修复 → 角色状态、事实、伏笔回灌 → 下一章

技术栈：React 19 + Vite + Express 5 + Prisma；编排用 LangChain + LangGraph；SQLite 默认，RAG 走 Qdrant；含 Electron 桌面版。

三个亮点模块：

  • 角色资源账本——按本章参与者筛选角色信息，避免把所有人全塞进 prompt（省 token 的关键）
  • 反 AI 规则引擎——专门去模板感
  • RAG 召回 trace——可以追踪「这一章到底召回了哪些历史片段」，方便排查失忆问题

术Agents' Room —— 把写作变成「编剧室开会」

google-deepmind/tell_me_a_story · 52 ⭐ · Gemini 1.5 Flash 底座

核心思路：模拟影视剧的 writers' room。任务拆成两类 Agent，由 Orchestrator 统一调度，所有产出写进共享的 Scratchpad（黑板记忆），后面的 Agent 都能读到前文。

PLANNING AGENTS

负责规划：分别处理冲突、角色、设定、情节，把「怎么写」这件事先想清楚。

WRITING AGENTS

负责执笔：按 Freytag 金字塔分段写——开端 / 上升 / 高潮 / 下降 / 结局。

有意思的做法：用「蒸馏反向翻译」——先让强模型从人类好故事里逆向抽出「计划」和「分段」，再微调小模型学会「怎么规划」。

成绩：平均约 3000 字（端到端基线约 1200 字），专家评测在情节、创意、人物发展、语言四个维度全面胜出。局限：框架代码未完全开源，只放出了数据集；量级仍是 3000 字，不是百万字网文方案。

简gpt-author —— 最简单的「链式生成」样本

mshumer/gpt-author · 2.5k ⭐ · Jupyter Notebook · 玩具级但极具启发

核心思路：就是一条链子，直接抄作业都行：

生成候选情节→ 选优→ 提炼书名→ 生成 N 章故事线→ 逐章写作
参考前文→ 生成封面 prompt→ 打包 EPUB

成本：15 章小说低至 4 美元、几分钟出稿。

作者自己列的问题：早期章节 token 会爆、章节常被截断、没有记忆压缩机制。所以它属于玩具级原型——但作为理解「链式生成」的起点，它是全网最好的教材。

🎯 从开源项目里能抄走的三条「干货」

  1. 状态文件外置法：维护三个文件——全书摘要、角色状态、剧情线，每写完一章就更新。这是最低成本的长篇管理方案，用记事本就能做，不需要任何编程。
  2. 按任务分工用模型：架构/大纲用逻辑强的（DeepSeek、Gemini），正文用文笔好的（Claude），审校用另一个模型专门挑逻辑错误。换模型 = 换个视角检查。
  3. 写新章前先做一次召回：不要凭记忆写下一章。先问 AI「根据前文，这一章登场的人物现在分别是什么状态」，让它去翻你的状态文件，再动笔。
05 / 创作方法论

工具只是笔，会写才是本事

前面讲的都是「怎么让 AI 帮忙」。但真正决定一本书能不能被人读下去的，是下面这些最朴素的东西。 好消息是：它们全都可以学，而且大部分是套路。

5.1 选题：写什么题材

💡 最有用的一条数据对比

番茄小说上：「传统玄幻」超 47 万本，单书平均读者不足 60 人；而「民俗志怪」不到 8000 本，单书平均读者超 1100 人。

结论很直白：在红海当炮灰，不如在蓝海当标杆。新人不要一头扎进最热的赛道。

判断一个题材能不能写：四问 + 三数据

先自问四个问题（答不上就别开）

  1. 我最常读什么类型？兴趣决定你能不能坚持到 100 万字。
  2. 我有什么别人没有的知识或经历？你的职业、地域、行业就是天然的壁垒。
  3. 我能稳定日更多少字？产能决定了你该选什么样的赛道上限。
  4. 这个题材的核心矛盾，撑得住三卷、上百章吗？撑不住就是短篇的命。

再去平台拉三个数据

  1. 同分类月新增书数 → 看市场容量有多大
  2. 榜单前 20 名的流量集中度 → 越低越容易分到流量
  3. 评论区高频吐槽 → 这是读者未被满足的真实需求，是最值钱的情报

创新公式：经典赛道 + 新兴元素。例如「无限流 + 中式民俗」「年代文 + 实业报国」。凭空自创世界观 = 把理解成本全甩给读者，冷启动极难。

5.2 爆点：怎么判断和打造

爽点 = 零件

单次情绪交付的小单位，读者「爽一下」就过去了。比如一次打脸、一次升级、一句嘴炮。
作用是让读者继续读。

爆点 = 烟花

多个爽点叠加、铺垫到位后引爆的情绪峰值 + 记忆点，能形成「名场面」和口碑传播。
作用是让读者主动安利。

爆点怎么「埋」和「爆」：H-I-P 公式

H · Hook 压力输入

制造焦虑、愤怒、好奇

用短句、断句，把读者的心提起来。

「门开了。没人。只有血。」

I · Intensity 压抑积蓄

张力累积

用中长句、心理描写、信息不对称，让读者越来越憋。

这一段越长，后面的爆就越响。

P · Payoff 释放

反击、揭晓、收获

用有力动词 + 短促结论，一击即中，别拖。

「枪响。人倒。钱到手。」

⚡ 两条必须记住的节奏铁律

  • 70% 的章尾要卡在 I → P 的转换瞬间。读者被「卡在半空」，就只能点下一章。如果卡在 P 之后，读者满足了就关掉了。
  • 不能连续 P-P-P。一直爽会麻木，必须穿插 H-H-H 或 I-I-I 让读者换气。

判断一个点子是不是爆点：可写性五问

1

主角在这件事里有明确想要的东西吗？

没有欲望 = 没有戏。主角必须「想要」，而且很想要。

2

阻力是谁？对手看起来比他强吗？

对手太弱，爽感就很廉价。要让读者真的替主角捏一把汗。

3

读者看到这里，会不会替主角憋气？

没有压抑就没有释放。这一点是很多人写爽文失败的根源。

4

这个爽点爽完之后，能不能牵出更大的麻烦？

如果不能，剧情就断档了。好的爽点是「升级打怪」，不是「通关结束」。

5

用一句话讲给朋友听，他会不会问「然后呢」？

说不清的就是不成立的。这个测试最简单也最准。

黄金三章：开篇必须完成什么

位置必须完成的任务硬性红线
第 1 章 抛冲突、立人设、埋悬念 前 300–500 字必须出冲突；前 300 字不写景、不铺垫、不介绍背景
第 2 章 金手指 / 核心设定亮相，顺带带出世界观 专有名词每章 ≤ 3 个；设定靠剧情带出来，不靠旁白说明
第 3 章 小高潮收束开局危机 + 引出更大矛盾 + 强钩子 章末必须留钩子
✗ 平淡写法

李雷是个普通大学生，20岁，住在A市，每天过着平凡生活。有一天……

读者：跟我有什么关系？划走。

✓ 钩子写法

「警告！宿主生命体征正在急速下降！」李雷睁开眼，发现自己被绑在手术台上，头顶无影灯刺得他睁不开眼。

读者：为什么？然后呢？

5.3 怎么把小说写好

人人物

「四要素钉死法」——动笔前必须想清：

  1. 主角是谁？（定位与初始状态）
  2. 他现在最麻烦的事是什么？（有压力的初始冲突）
  3. 他最想得到什么？（短期目标 + 深层欲望）
  4. 谁或什么在拦着他？（具体对手）

立体人物公式：表面身份 + 秘密欲望 + 致命弱点 + 矛盾行为。

配角的低效写法是「有朋友有敌人」；高效写法是「导师是旧案嫌疑人、搭档是受害者家属」——让关系与主线纠缠在一起。

人物弧光五步：设定主性格 → 加辅助性格（对外泼辣，对内心软）→ 用他人对比强化 → 安排违背性格逻辑的事件制造挣扎 → 写出转变。

铁律：没人爱看完美人设。有缺点的人才真实，欲望才是驱动剧情的发动机。

界世界观：够用就好，别得「设定癌」

新手只需要写清楚 4 件事：时代/技术背景、规则体系（等级/职场/豪门规则）、地域格局、核心冲突来源。

有效设定三问：

  1. 它给主角什么机会？
  2. 它制造什么限制？
  3. 它把主角推向什么选择？

不能改变人物行动、也不能改变故事走向的设定，就是装饰。

原则：剧情先行，设定后置。人物用到什么就解释什么，剧情走到哪就铺到哪。开篇像说明书，读者直接闪退。

结构：三级大纲

层级写什么篇幅作用
总纲核心矛盾 + 主角成长弧线 + 结局方向1000–3000 字判断每一章是否在服务整个故事
卷纲每卷 2–3 件大事、主角状态变化、卷末钩子每卷 500–1500 字防中段失控、防烂尾

节奏：张力曲线与断章

四个配比参考

  • 快慢 3:1——3 章紧张配 1 章缓冲
  • 黄金速度——爽点间隔不超过 4 万字
  • 信息密度——约 300 字一个小起伏、500 字一个钩子、一章一个悬念
  • 章末钩子配比——危机型 30%、悬念型 25%、反转型 20%、机遇型 15%、升级型 10%

断章四原则

  • 在情绪最高点断
  • 在悬念刚抛出时断
  • 在反转刚发生时断
  • 在信息差最大时断

自检：如果连续三章都回答不出「主角目标变了吗？敌人压力升级了吗？读者信息增加了吗？关系位移了吗？」——你的节奏就是在原地打转。

三个可以直接套用的章节模板

起承转爽

最通用的模板

起（回顾 + 引冲突）→ 承（压力升级）→ 转（转折）→ 爽（反击 + 钩子）

过山车

适合高潮章

紧张 → 喘息 → 更紧张 → 假结局 → 最高潮 → 钩子

信息递进

适合悬疑/推理

线索 A → 结论 1 → 发现不对 → 线索 B 推翻 → 更大秘密

对话与描写：怎么写出画面感

情感不「说」，要「做」

✗ 直接说情绪

她感到非常悲伤。

✓ 用动作传递

她没有哭出声。只是把那条围巾叠好，放进抽屉最里面，关上。然后继续煮饭。

对话要「保护自己」，不要「说明自己」

真人不会说「我嫉妒你所以抢你功劳」，而会说：

「你别把话说得那么难听，这项目也不是你一个人的功劳吧。」

环境描写只抓一到两个关键感官就够：集市抓声音和气味，审讯室抓灯光和沉默。景物必须服务人物当下的情绪，杜绝全景式堆砌。

视角别乱：主角不知道的事别写出来，否则就是「开天眼」，读者瞬间出戏。

文风与「AI 味」：闻到就改

AI 味五大标志怎么改
① 「首先……其次……最后……综上所述」逻辑写在路标上了 —— 小说不需要路标
② 每段都是「总—分—总」小说段落应该是「动作—反应—结果」
③ 情感词汇堆砌但传递不到：他感到无比愤怒换成行为描写
④ 形容词通货膨胀：非常 / 极其 / 无比 / 深深 / 彻底全文搜索，删掉大半
⑤ 永远正确的废话：「人生充满挑战，只要坚持就能克服困难」整句删掉，一句都不留

🧹 去 AI 味四步流程

  1. 全文检索删除连接词套话（首先/其次/综上/因此/总的来说）
  2. 扫描情感标签，全部换成行为描写
  3. 通读删掉「删了也不影响」的句子——通常能删掉 20%
  4. 注入一次性细节，替换通用表述（不是「一家餐厅」，而是「门口挂着褪色塑料灯牌的面馆」）

建立个人风格锚点：先写 500 字文风样本，提炼专属习惯——固定偏好句式、标志性小动作、常用标点、环境描写不超过三行——然后要求自己全程遵守。

⚠️ 番茄等平台已明确严查纯 AI 生成。用 AI 理大纲可以，正文自己写并留底稿。

5.4 扑街清单：十个最常见的死法

#症状读者反应怎么改
1开篇堆设定、堆世界观直接闪退剧情先行、设定后置；第一章只留钩子和冲突
2第一章写回忆、主角原地不动三句话看不到当下剧情就划走必须有行动、选择、变化；静态抒情是毒点

7节奏拖沓、无冲突也写一章追更率下跌「无冲突不写章」；每章一小冲突 + 一小进展 + 一钩子

06 / 完整流程

从选题到完稿：一条能跑通的路线图

前面把「工具」「开源思路」「创作方法论」三块都讲完了。这一节把它们拧成一股绳—— 每个阶段该做什么、产出什么、AI 在哪一步能帮上忙、哪一步绝对不能交给 AI。

🔗 三块内容是怎么拼在一起的

开源项目总结出的「记忆外置 + 按任务分工模型 + 写前召回」三条干货，正好对应创作流程里的骨架搭建、写稿、质检三个阶段。换句话说：大神们用代码实现的自动化流程，你用三个文档 + 三个聊天窗口，可以手动复刻出七八成效果。

六阶段实战路线图

PHASE 1

立项：决定写什么、写给谁看

  • 用「四问 + 三数据」筛选题材，锁定一个半热不热的蓝海细分
  • 用「经典赛道 + 新兴元素」公式做出差异化
  • 确定目标平台（不同平台的红线和读者口味完全不同）
产出：一句话卖点 · 目标平台 · 题材定位文档
🤖 AI 怎么用：让 DeepSeek 帮你分析「这五个细分赛道，哪个竞争更小、更适合新人」，或者让它列出某题材的常见套路与已饱和的点子。但最终拍板必须是你——因为只有你知道自己能写什么、能坚持多久。
PHASE 2

骨架：搭设定、立人物、写大纲

  • 用「四要素钉死法」确定主角，「立体人物公式」补完配角
  • 写清世界观的 4 件事，用「有效设定三问」砍掉没用的设定
  • 写三级大纲：总纲 → 卷纲 → 最近 20 章的章节卡
  • 顺手建三个状态文件（这是从开源项目抄来的）：全书摘要、角色状态、剧情线
产出：设定文档 + 三级大纲 + 三个状态文件（用普通文档就行）
🤖 AI 怎么用：这是 AI 价值最高的环节之一。把人物设定丢给它，让它推演冲突、检查逻辑漏洞、生成大纲候选。也可以用笔灵AI 这类工具直接出爆款大纲做参照。注意：AI 出的大纲会很「标准」，你需要手动加入一个它想不到的转折。
PHASE 3

包装：书名、简介、目录

  • 书名：反差 + 卖点，控制在 15 字内
  • 简介：一句话讲清「身份 + 核心冲突 + 最大看点」
  • 这三件套直接决定首页点击率——写得再好，没人点开也白搭
产出：吸量三件套（书名 / 简介 / 目录）
🤖 AI 怎么用：让 AI 一次生成 20 个书名备选，你从中挑。这是典型的「AI 出量、人做判断」。但别让 AI 直接定——它取的名字往往很模板化。
PHASE 4

写稿：写正文（占整个工作量的 60%）

  • 优先死磕黄金前三章：第 1 章前 300–500 字必须出冲突，第 3 章章末必须留强钩子
  • 之后逐章推进：每章一小冲突 + 一小进展 + 一钩子
  • 用「起承转爽」「过山车」「信息递进」三个模板轮换着写
  • 每写完一章就更新状态文件，再写下一章
产出：正文初稿
🤖 AI 怎么用（这里要特别小心）：
  • 可以：卡文时让它给三个剧情走向供你选；让它写一段环境描写你再改；写完自己的一章让它挑逻辑漏洞。
  • 不建议：让它整章生成。除了平台红线问题，更实际的原因是——AI 的段落单独看没问题，连起来就是流水账，后期你会发现改它的稿比自己写还累。
  • 关键动作：写新章之前，先让 AI 根据你的状态文件回答「这一章该出场的人物现在分别是什么状态、有哪些未回收的伏笔」。这一步能直接解决 80% 的「吃书」问题。
PHASE 5

质检：逐章打分 + 去 AI 味

  • 逐章自检四问：主角目标变了吗？敌人压力升级了吗？读者信息增加了吗？关系位移了吗？
  • 画一条「爽点—节奏曲线」，找出低洼区（连续几章没有起伏的地方）
  • 跑一遍「去 AI 味四步流程」
  • 对照扑街清单十条，逐条排查
产出：修改清单 + 修订稿
🤖 AI 怎么用：把某几章丢给换一个模型（不是写的那一个），让它专门找逻辑矛盾和角色前后不一致——这就是开源项目里「用不同模型干不同活」的手动版。让它做校对、错别字检查也完全没问题。
PHASE 6

归档：沉淀下一本可复用的经验

  • 正文、设定、复盘分文件夹存放
  • 把这本书踩过的坑、验证有效的模板记下来
  • 数据复盘：哪一章掉得最狠就从哪一章改起
产出：素材库 + 个人写作方法论
🤖 AI 怎么用：让 AI 帮你把这本书的写作过程做成结构化总结，沉淀成下一本可以直接复用的模板。这是让第二本书比第一本轻松的关键。

几个容易踩的现实问题

平平台怎么选

平台模式签约门槛适合谁
番茄免费 + 广告分成满 2 万字可申请纯小白试水、快节奏爽文
起点付费订阅内投 1 万字，通过率约 15–20%有文笔野心、能熬长期
晋江付费订阅签「人」不签「文」女频言情
七猫免费 + 广告（有保底）真人编辑审核求稳定现金流
飞卢冲榜2 万字签约、12 万字上架脑洞大、能日更 6000+

一句话：求稳→七猫；赌上限→番茄；赌长期→起点；写女频→晋江。选定一个平台，至少写完一本 50 万字再换——频繁换平台是最大的沉没成本陷阱。

时时间与字数怎么管

  • 日更底线：番茄首秀期建议 6000 字/天，起点保底 4000 字/天。断更 48 小时，算法会默认「内容不稳定」。
  • 固定写作时段：例如每晚 20:00–22:00，前一晚先写次日 2–3 句章节梗概。
  • 写作纪律：写作期间关手机；先一口气写完初稿，过程中不回头删改；写完只修病句，不做大篇幅剧情改动。
  • 存稿 3–7 天，用存稿箱定时发布。
  • 卡文急救：给主角制造新困境、让对手加压；过渡章可以跳过，优先写关键剧情。
  • 数据复盘：每天花 5 分钟看后台，哪一章掉得最狠就从哪一章改起。

📊 三条参考及格线（不同平台口径有差异，仅作量级参考）

  • 番茄书架比 / 追更比及格线约 35%
  • 前 10 章完读率低于 8%，基本就腰斩了
  • 脑洞文 10 万字完读率 ≥15%、爽文 ≥10%
07 / 行动清单

如果你今天就想开始，照着做

不用全部想清楚再动手——那永远不会开始。下面这份清单，按顺序做就行。

第 1 天：准备

  1. 注册一个通用大模型（DeepSeek 免费就够）
  2. 建一个文件夹，里面建四个文件：设定.md、总纲.md、角色状态.md、剧情线.md
  3. 花两小时泡在平台榜单上，只看不写——看前十名都在写什么、书名怎么起、简介怎么写

第 2–3 天：定方向

  1. 用「四问 + 三数据」选出你的题材，写下一句话卖点
  2. 用「四要素钉死法」定主角，「立体人物公式」补两个配角
  3. 写 1500 字的总纲：核心矛盾 + 主角成长弧线 + 结局方向
  4. 把最近 20 章做成章节卡（每章 50–150 字）

第 4–6 天：死磕前三章

  1. 第 1 章：开头 500 字内出冲突，不写景不铺垫
  2. 第 2 章：金手指亮相，世界观靠剧情带出
  3. 第 3 章：收束开局危机 + 引出更大矛盾 + 强钩子收尾
  4. 写完自己读一遍：如果三章读完你不想看第四章，重写

第 7 天起：稳定推进

  1. 每天固定时段写，先定当日目标字数
  2. 写新章前，先让 AI 汇报「人物当前状态 + 未回收伏笔」
  3. 写完一章，立刻更新角色状态和剧情线两个文件
  4. 每 10 章做一次质检：跑自检四问 + 去 AI 味流程
  5. 存稿 3–7 天再发布

🎯 最后一句，也是最重要的一句

先写完，再写好。第一本书的目标不是成神，而是完本—— 完本能力才是这个行业最稀缺的东西。绝大多数人不是输在写得不好，而是输在没写完。

AI 能帮你省掉查资料、想大纲、改病句的时间，但它不能替你坐下来写那 3000 字。这一点，2026 年和一百年前没有任何区别。
