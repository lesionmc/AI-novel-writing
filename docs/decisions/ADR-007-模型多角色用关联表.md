# ADR-007: 模型多角色用关联表（provider_role），而非单值字段

## Status
Accepted (2026-09-23)

## Background

每个模型配置行 `llm_provider` 只有**一个** `task_role` 字段（`NOT NULL DEFAULT 'content'`）。
任务是分角色的：写大纲（`outline`）、写正文（`content`）、一致性审校（`review`）、向量嵌入（`embedding`）。

于是「同一个模型能不能同时干几件事」这个再自然不过的诉求被卡住了：
把模型 A 指给 `review`，它原来在 `outline` 上的分配就被抢走。

契约层面还有一层叠加限制：`task_role` 是 `NOT NULL`，而契约把
`PATCH task_role: null` 定义为「**不修改**」而不是「清空」——
**这套契约里根本不存在"解除分配"这个操作。**

用户实测直接撞上并明确反馈：
> 「为什么不能选择多个一样的模型」「能不能一个 ai 做完全部，全部都能做」

（更早的 `OD-02` 曾决议"不改表结构"，理由是"要动 5 个消费点 + 迁移"。
事后看这个取舍算错了：省一次迁移，换来一个用户每天都会碰到的能力缺失。）

## Decision

**新增关联表，不改 `llm_provider.task_role` 的存储语义。**

```sql
CREATE TABLE IF NOT EXISTS provider_role (
    provider_id INTEGER NOT NULL,
    task_role   TEXT    NOT NULL,
    created_at  TEXT    NOT NULL,
    PRIMARY KEY (provider_id, task_role)
);
CREATE INDEX IF NOT EXISTS idx_provider_role_role ON provider_role(task_role);
```

要点：

1. **`(provider_id, task_role)` 作主键** —— 天然支持"一个模型挂多个角色"，
   也天然支持"一个角色有多个候选模型"（既有行为，界面本来就有"多模型抢同一角色"的提示）。
2. **必须放进 `schema.sql` 的 `@@GLOBAL` 条件块** —— `llm_provider` 是**全局库**表，
   关联表若落在书库里，全局库永远不会有它。
3. **`schema_loader._GLOBAL_TABLES` 必须同步加上这张表** —— 它是一份**硬编码的表名副本**，
   漏加的症状是：**新建的库有表、已存在的库永远补不上**（静默失配，不报错）。
   这是审计 A-09 那条隐患的又一次实际发作，已用测试锁住。
4. `find_for_role()` 改联表查；**`find_default()` 保留为回退** ——
   这是"一个模型全包"（所有角色都不指定 → 全走默认模型）能成立的前提。
5. `PATCH /api/providers/{id}` 接受 `task_roles: list[str]`：**整体替换**，传 `[]` = **解除分配**。
   （补上了一个此前**根本不存在**的能力。）
6. `LLMProviderOut` **新增** `task_roles`，**保留** `task_role` 字段不动 —— 不破坏现有前端类型与契约。
7. 迁移 `services/provider_role_migration.py`：读**全局库**；`INSERT OR IGNORE` 天然幂等；
   另加**一次性标记** `meta.provider_roles_migrated_v1`；失败只 `WARN` 不抛。
   - **为什么还要一次性标记**：只用"目标表有没有行"当判据，会导致
     **用户取消分配后重启又把旧分配复活**。这个坑项目里踩过
     （`provider_migration.py` 的注释里记着），这里照同一模式处理。

## Consequences

**正面**
- 一个模型可以同时承担多个角色，"一个模型全包"从"需要绕"变成"点一下"。
- 顺手补上了"解除分配"能力（此前契约里根本没有）。
- 向后兼容：旧字段保留、旧客户端不受影响、老库靠一次幂等迁移补齐。

**负面 / 代价**
- 新增一张表 + 一次迁移 + 一个幂等标记（复杂度换能力，这次是划算的）。
- `task_role` 旧列成为**冗余镜像**（保留作"首要角色"与历史数据；空集合时不改动它）——
  属于**已知的技术债**，将来若要彻底清理需另开一次迁移。

**验证**
- 后端 `pytest` **238 tests / 0 failures / 0 errors / 0 skipped**（原 227 + 新增 11）。
- schema 派生副本对账 `--check` 退出码 0、维 1 维 2 双 PASS。
- 覆盖用例：①一个 provider 同挂 `outline`+`content`+`review` 三角色都能被取到
  ②迁移幂等 + 取消分配后重启不复活 ③该角色无模型时仍回退默认模型 ④`ollama`（免密钥）语义不变。
