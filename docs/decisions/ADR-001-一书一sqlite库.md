# ADR-001: 一本书一个 SQLite 库

## Status: Accepted (2026-09-20)

## Background

产品为**本地运行、单用户单机**的开源工具，无账号体系、无云端、无并发设计。核心诉求是：整个作品（设定、章节、状态、向量、日更）能**零配置**地用、能**简单备份与迁移**、且**单书损坏不波及其他书**。同时需要支撑“多书项目管理（R15）”。

关键约束来自《12-需求变更记录》§4：存储决策已冻结为“一本书一个 SQLite 库”。

## Decision

采用 `books/<slug>/novel.db` —— **每部作品一个独立 SQLite 库文件**，书本元信息同时写入同目录 `meta.json` 以便快速列举；书库列表通过扫描 `books/` 目录读取 meta，不维护全局库。

- 建库：新书即执行 `05-数据库schema.sql` 建出全量对象（15 普通表 + 3 虚拟表）。
- 迁移：每库独立执行版本化迁移，`PRAGMA user_version` 记录版本。
- 备份：复制整个 `books/<slug>/` 目录即完成备份（含 WAL/SHM）。

## Consequences

**正面**
- 备份/迁移 = 拷贝文件夹；恢复 = 放回文件夹（TC-36）。
- 单书损坏、schema 迁移失败的影响被隔离在单书内。
- 无需全局库，避免“目录 + 全局库”双写不一致。
- 天然契合“删除作品 = 移入回收目录”。

**负面 / 代价**
- 跨书全局查询（如全库统计、跨书搜索）需遍历各库，M1 无此需求。
- schema 变更需对每个已存在的库**逐库迁移**（迁移脚本必须幂等、可回滚）。
- WAL 模式产生 `-wal`/`-shm` 三个文件，任何备份/迁移必须整目录处理，只拷 `.db` 会丢最近事务。

## Related ADRs

- ADR-002（双路召回架构）：向量库随书库一起迁移。
- ADR-003（手写 SQL 不上 ORM）：`schema.sql` 作为每库唯一真相源。
