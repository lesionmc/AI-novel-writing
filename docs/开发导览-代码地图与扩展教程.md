# 开发导览：代码地图与扩展教程

> **这份文档给谁看**：接手这个代码库、要改点东西的人。
> `README.md` 讲「怎么用」；`docs/spec-*.md` 讲「要做成什么」；**本文讲「代码在哪、怎么改」**。
> 如果你只想知道怎么启动：看 README。想加一个页面 / 一个接口 / 一个主题：看本文第 5 节。

## 1. 三十秒进入开发态

```bash
# 后端（改完重启即可，不需要热重载）
cd ai-novel/backend
../.venv/Scripts/python.exe -m app          # Windows；打印端口（默认 5210）

# 前端（热更新）
cd ai-novel/frontend
VITE_API_TARGET=http://127.0.0.1:8756 npm run dev    # → http://localhost:5173
```

两个必须知道的点：

- **端口默认可预测：5210**。启动时优先用 5210（脚本 / 书签 / 文档里的地址重启后依然有效），
  被占用才自动挑空闲端口；要指定就 `AINOVEL_PORT=8756`（E2E 与多实例场景就是这么用的）。
- **开发态用 Vite 代理，生产态同源托管**。`vite.config.ts` 把 `/api` 代理到
  `VITE_API_TARGET`；打包后由 FastAPI 的 SPA 兜底路由直接吐 `dist/index.html`，
  前端一律用 `/api/...` 相对路径，不区分环境。

**单实例保护**：一个进程启动时会去抢 `data/instance.lock`。第二个进程会直接拒绝启动并
打印中文提示 —— 这是为了防止两个进程同时写同一个 `books/` 目录导致覆盖丢稿。
开发时如果改了启动逻辑没退出干净，删掉 `data/instance.lock` 即可（正常不会残留）。

## 2. 代码地图：目录 → 职责

### 后端 `backend/app/`（分层严格，依赖只向下）

| 目录 | 职责 | 说话方式 |
|---|---|---|
| `main.py` | **只装配**：中间件 + 路由注册 + SPA 兜底。**零业务逻辑** | — |
| `__main__.py` | 启动入口：版本校验 → 抢单实例锁 → 选端口 → 开浏览器 → 跑 uvicorn | — |
| `routers/` | HTTP 层：解析入参、调 service、返回 model。**不写业务规则** | 每个文件一个领域 |
| `services/` | **业务规则与编排**。禁止 import fastapi 的 `Request`/`Response` | 一个用例一个 service |
| `services/audit/` | 质检能力：`aho_corasick.py`（手写多模式匹配）、`normalize.py`（归一化）、`wordlist.py`（词库加载缓存）、`ai_flavor.py` + `rules_ai_flavor.py`（去 AI 味词表与评分）、`sensitive.py`（扫描编排） | 纯本地、不依赖模型 |
| `services/llm/` | 模型客户端、模型发现、提示词、JSON 容错解析 | `clients.py` / `discovery.py` / `prompts.py` / `json_chat.py` |
| `repositories/` | **唯一写 SQL 的地方**（手写 SQL，不用 ORM） | 一张表一个 repo |
| `models/` | Pydantic 出入参模型（契约的代码化） | 按领域分文件 |
| `db/` | 连接层、能力探测、作品注册表、schema 加载 | `connection.py` / `registry.py` / `schema_loader.py` |
| `prompts/` | 提示词模板（与 `08-提示词规格.md` 对齐） | — |
| `tests/` | pytest，100 个用例。**契约改了必须同步改这里** | — |

### 前端 `frontend/src/`

| 目录 | 职责 |
|---|---|
| `api/` | **唯一网络出入口**。`client.ts` 按端点分组封装，业务组件禁止直接 `fetch` |
| `hooks/queries.ts` | 所有读操作（TanStack Query）。`hooks/mutations/` 是所有写操作 |
| `components/` | 按业务域分组：`common`（无业务通用件）/ `writingdesk` / `config` / `library` / `outline` / `stats` / `topics` / `audit`（质检页三区块） |
| `components/common/Icon.tsx` | **全项目图标唯一入口**（lucide-react 只允许在这里 import） |
| `pages/` | 路由页面，负责组装，不写细节逻辑 |
| `stores/` | Zustand：`deskStore`（写作台瞬态）、`toastStore`、`themeStore` |
| `styles/` | `design-tokens.css`（**颜色唯一真相源**）+ `global.css`（重置与根级样式） |
| `lib/` | 纯函数工具（`theme.ts` / `format.ts` / `chunkLocate.ts` …），**不放副作用** |
| `types/` | TS 类型。`api.d.ts` 与 `06-API定义-openapi.yaml` 对齐 |

## 3. 一次请求的完整生命周期

以「点『完成本章』」为例，照着这条链找代码，任何功能都能顺藤摸瓜：

```
前端点了按钮
  → components/writingdesk/TopBar.tsx          触发 onFinalize
  → hooks/queries.ts + hooks/mutations/*.ts    拿到 mutation 函数
  → api/client.ts                              封装成 POST /api/chapters/{id}/finalize
  → api/request.ts                             统一加错误处理 / 解析
──────── HTTP ────────
  → routers/chapters.py                        解析 chapter_id
  → services/writeback.py                      业务规则：调模型、解析建议
  → services/llm/json_chat.py                  调模型 + JSON 容错（重试 2 次后 400）
  → repositories/*.py                          只有这里写 SQL
  → books/<slug>/novel.db                      一書一库
──────── 返回 ────────
  → components/writingdesk/WritebackDialog.tsx 弹窗展示建议
  → 用户逐条确认 → POST .../finalize/confirm → 才真正入库（红线 2）
```

**记住这条链的形状**：`页面 → hook → api → router → service → repository → DB`。
在这条链上任何一环加东西，都要按同样的位置放，别跨层。

## 4. 数据在哪，怎么进去

- **一本书一个 SQLite 库**：`books/<书名>/novel.db`。切换作品 = 切换库路径。
- **表结构唯一真源**：`backend/app/db/schema.sql`（`schema_loader.py` 读的就是它）。
  建库时会按运行时能力**条件化执行**：FTS5 不可用就不建 `chapter_fts`，
  sqlite-vec 不可用就不建 `vec_chunk`（用 `-- @@OPTIONAL fts|vec` 标记包住）。
  **不这么做的话，缺扩展的机器会在建书第一步就整体失败。**
- **`05-数据库schema.sql`（仓库根目录那份）是派生副本**，由真源同步生成，**不要手工改**。
  校验：`python docs/tools/sync_handover_schema.py --check`
- **密钥不进库**：`llm_provider` 只存 `key_ref`（引用名），密钥本体在系统密钥环。

## 5. 五个扩展场景：照着做

### 场景 A：加一个主题

1. `frontend/src/styles/design-tokens.css` 末尾加一块，**只覆盖语义色层**：
   ```css
   :root[data-theme='你的id'] {
     color-scheme: dark;            /* 或 light，让原生控件跟随 */
     --color-bg: #...;
     --color-surface: #...;
     /* …把 62 个语义 token 全覆盖一遍（派生型可省，见下）*/
   }
   ```
   > 派生 token（`--color-info-*`、`--color-importance-*`、`--color-status-*`）
   > 值形如 `var(--color-primary)`，上游覆盖了它们自动跟随，**不用重复写**。
2. `frontend/src/lib/theme.ts` 的 `THEME_LIST` 加一条（id / 标签 / 一句话说明 / 图标 / 色卡 / scheme）。
   图标要先用 `components/common/Icon.tsx` 里已有的语义名，没有就去 `types/ui.ts` 加。
3. `frontend/index.html` 内联脚本里的 `VALID` 数组加上新 id（防白闪要用）。
4. `ai-novel/docs/design-tokens.json` 的 `themes.list` 加一条登记。
5. **跑 `npm run check:theme`** —— 它会告诉你漏了哪个 token、哪个颜色对比度不达标。

**组件一行都不用改。** 这就是 token 化的收益。

### 场景 B：加一个页面

1. `frontend/src/pages/XxxPage.tsx`（组装页，细节放 `components/<域>/`）
2. `frontend/src/App.tsx` 加 `<Route>`
3. 数据用 `hooks/queries.ts` + `api/client.ts` 里加端点，**别在页面里直接 fetch**

### 场景 C：加一个 API 端点

1. **先写契约**（契约先行，它是团队唯一依据）：
   `06-API定义-openapi.yaml`
   > ⚠️ 注意：契约文件**不在本仓库内**！它在**本仓库的上一级目录**（与 `ai-novel/` 同级），
   > 因为它是「交接包」的一部分而不是代码的一部分。
   > 划任务边界时（例如"只许改 frontend/**"）要单独点名它 —— 写成相对路径即可，
   > **不要写死盘符**（本项目要在多台机器间迁移，绝对路径一定会失效）：
   > ```bash
   > # 从 ai-novel/ 里看，契约在上一级
   > ls ../06-API定义-openapi.yaml
   > ```
2. `backend/app/models/` 出入参 → `routers/` 挂路由 → `services/` 写规则 → `repositories/` 写 SQL
3. `backend/tests/` 加用例；`frontend/src/api/client.ts` + `types/api.d.ts` 同步
4. 改完**对一次账**：`app.openapi()` 的 path / operation 数应与契约一致
   （契约里标了 `x-m1-scope: deferred` 的端点**允许未实现**，对账时要先剔除）

### 场景 D：加一张表

1. 改 `backend/app/db/schema.sql`（真源），**别忘了**：实体表直接写、
   虚拟表（FTS / vec）必须用 `-- @@OPTIONAL` 标记包住
2. 同步 `05-数据库schema.sql`：`python docs/tools/sync_handover_schema.py --write`
3. 跑 `--check` 验证两维一致；老库靠 `PRAGMA user_version` 判断是否迁移

### 场景 E：改一个颜色 / 间距

只改 `frontend/src/styles/design-tokens.css`，并同步 `docs/design-tokens.json`。
**组件里出现硬编码色值一律算 bug**（唯一例外 `#fff` / `#000`）。

## 6. 六条铁律（都是踩过坑换来的）

1. **三条红线不可违反**：写前召回自动触发、章末回写必须人工确认、不配模型全功能可用。
   改任何代码前先确认没碰这三条。
2. **颜色只走 token**。硬编码色值 = 换主题时必然漏。
3. **契约先行 + 改完对账**。`06-openapi.yaml` ↔ `app.openapi()` 要能逐条对上；
   注意 **path 数和 operation 数要分开报**，混着说一定出误会。
   **当前实测口径（2026-09-22 复核）：契约 40 path / 57 operation，代码 39 / 56，
   差集恰好 1 条** —— 即 `POST /api/books/{book}/audit/consistency/stream`（标 `x-m1-scope: deferred`）。
   对账时**先把 deferred 的剔除再比**，否则会把"主动冻结"误判成"漏做"。
   <br>⚠️ 顺带记一句实测发现：契约里对**单资源路径参数**统一写作 `{id}`，
   而代码用的是 `{char_id}` / `{chapter_id}` / `{provider_id}` 这类带前缀的名字
   （URL 形状完全一致，只有参数名不同，运行期无影响）。
   这不影响功能，但严格按契约生成 client 的工具可能报参数名不匹配 —— 已登记，
   **不打算为它改动 16 个路由的处理函数签名**（零功能收益、高回归风险）。
4. **凡「部分字段更新」的仓储方法，都要有一条测试断言白名单外字段不会被静默接受**
   （历史事故：回写传入的 `status` 被 allowlist 静默丢弃，全程零报错）。
5. **序列化 / 状态基线一律按值比较，不按引用**。历史事故：`Object.is` 比对象身份，
   导致每次切章都空写一次库。凡「值等于基线就不脏」这类语义，实现就必须按值比。
6. **Windows 下含中文的 `.bat` 必须存 cp936**，否则整段 `if` 块解析错乱、
   连错误处理都失效（退出码还是 0，看起来"跑了"其实全错）。

## 8. 这台机器的环境限制（做自动化前必读）

> 这些不是代码问题，是**宿主环境**的限制。踩一次浪费十几分钟，所以写在这里。
> （2026-09-22 复核时逐条实测确认；项目记忆 `pitfalls.jsonl` 里有对应条目。）

| # | 限制 | 现象 | 绕法 |
|---|------|------|------|
| 1 | **Bash 工具是残的** | Git 自带 coreutils 缺失，`dirname` / `cd` / `ls` / `head` / `which` / `wc` **全部 command not found**，调用即 exit 127 | 需要 shell 的操作**一律走 PowerShell 工具**；纯文件操作走 Read/Glob/Grep |
| 2 | **PowerShell 工具不回显 stdout** | 只显示 `Command completed with exit code 0`，看不到任何输出 | 结果**先落文件**（`Set-Content` / `Out-File`），再用 Read 读回来；退出码单独写一行 |
| 3 | **子进程会被强制回收** | 用 `&` 后台或 `Start-Process` 起的服务，**在本次工具调用结束后被杀**（无关闭日志、锁文件残留） | 两种办法：① **起服务 + 打接口 + 收进程写在同一条命令/同一个脚本里**（推荐，见 `bootstrap.py` 的做法）；② 需要跨会话常驻时用 **Windows 计划任务**（父进程是任务计划服务，不受会话影响） |
| 4 | **运行时编译 .NET 被拦** | `Add-Type` 报 "compiles and loads .NET code at runtime" | 用不了 `Microsoft.VisualBasic.FileIO` 的回收站 API。要做"可恢复删除"就**自建清理目录 + `Move-Item`**（完全可恢复，且不依赖被禁 API） |
| 5 | **从 Bash 调 `cmd.exe` 被拦** | 含 `cmd /c` 的命令串会被安全策略扫描拦截 | 需要 cmd 的操作（如 `schtasks`）**走 PowerShell 工具**执行 |

### ⚠️ 一个容易自己骗自己的坑：**"假乱码"**

用 `Out-File -Encoding UTF8` 去接 Python 的 stdout 时，PowerShell 会**按系统码页（GBK）解码**，
于是 UTF-8 输出会变成一坨乱码。**这不是程序的问题，是取证环节的问题** ——
`bootstrap.py` 在真实双击出来的控制台里显示正常（Python 走 `WriteConsoleW`，与码页无关）。

判断办法：把同样的命令在真实控制台里跑一遍；或者让脚本**直接写文件**（`encoding="utf-8"`）而不是靠管道。
**不要把自捕获伪影当成 bug 上报。**

> **三个环境陷阱**（都真实踩过，别再花时间重踩）：
> 1. **`AINOVEL_PROJECT_ROOT` 会把前端 dist 的路径一起挪走** → 后端认为"前端未构建"，
>    返回的是 JSON 提示而不是 SPA，页面自然什么都不渲染。所以必须先 `cp -r dist` 进隔离根。
> 2. **pytest 退出码可能是 1 而 junit 显示 0 失败** —— 沙箱的批量删除守卫拦截了
>    pytest 清临时目录。把 `TMP/TEMP` 指到独立空目录即得 exit=0；**以 `--junitxml` 为权威计数**。
> 3. **stdout 会被吞**（连 pytest 的 `140 passed` 汇总行都不出现）→ 取证一律落文件再读，
>    或重定向到文件。**"grep 不到" ≠ "没通过"。**

- [ ] 三项前端门禁 + pytest 全绿
- [ ] 动过主题 → `npm run check:theme` 全绿（三项：覆盖完整性 / 对比度 / JSON 登记）
- [ ] 动过主题或质检页 → 真实浏览器端到端通过，截图落在 `docs/theme-shots/` / `docs/audit-shots/`
- [ ] 动过契约 → **跑 `python docs/tools/check_contract_parity.py -v` 且 exit=0**（对账 path 集合、
      operation 数、**method-per-path** 三项）；**且 yaml 的 `info.description`/tag 描述没有停留在旧口径**
- [ ] 没有新增硬编码色值、没有 emoji 当图标、没有单个文件超 300 行
      （行数已由 `frontend/eslint.config.js` 的 `max-lines` 门禁强制执行，`npx eslint .` 报红即失败；
      唯一豁免：`styles/design-tokens.css` —— 它是纯数据、不经过 eslint，且刻意把所有颜色收在
      一个文件里，改配色不用到处找）
- [ ] 三条红线仍成立（无模型时本地功能照常可用）
- [ ] **质检页永不写入正文**：任何"帮你改"的入口都不得触发章节 PATCH（有端到端用例锁死）
